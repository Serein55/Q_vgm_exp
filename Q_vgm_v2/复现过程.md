# v2 复现过程

## 2026-09-28：采用实施计划，完成第一批核心模块

- 按用户的《Q-VGM v2 复现实现与实验计划》建立独立 `Q_vgm_v2/`，未修改 v5 核心。
- 实现 2304 维状态投影、两头逐位置 Q/V、stepwise IQL 损失、target EMA、单条 buffer 边界转换。
- 路径集中在 YAML。decoder 冻结、ReLU、timeout、学习率和更新预算等不能视为已核实作者设置；尚未启动训练。
- CPU 单元测试 **9/9 通过**：包括 terminal/partial/timeout、跨 chunk bootstrap、逐位置 min、Q/V 梯度隔离。仅证明这些局部契约，不代表环境复现成功。
- 当前 SFT fullsuite 目录可见日志、视频和 TensorBoard；尚未确认完整 500 条 observation/prefix/action 数据。旧 v5 buffer 不直接算作 v2 正式数据。
- 下一步：核实可复用轨迹及 expert demos，完成动作归一化和统一 buffer，再启动 AE/critic。Q-selection / Q-guidance 通过之前不训练 actor。

原文：[arXiv v2](https://arxiv.org/abs/2606.08015v2)。其 Spatial 数据表列出 500 条评估轨迹和 432 条 demos；本地尚未完成对应数据准备。

## 2026-09-28：全新 SFT 数据采集

用户决定重新采集。配置 `configs/collect_sft.yaml`，使用 released few-shot SFT，Spatial 10×50 条；policy H10/D32、执行 H5/D7、10 denoising steps，T=1、额外 flow noise=0、最多 220 步、settle 10 步，seed=7。这些采样设置不冒充作者已公开超参。

通过 tmux `qvgm-v2-sft-collect` 启动，GPU 2 负责 task 0–4，GPU 3 负责 task 5–9。保存 observations、frozen VLA prefixes、归一化 action、逐步奖励、terminated/truncated、seed、初始状态编号及 `success_once`。首次成功即结束，故本协议下 `success` 与 `success_once` 相同；settle 阶段不计入策略成功统计。

入口：`bash Q_vgm_v2/scripts/collect_sft.sh`（从 Q_vgm 根目录）；按完整 episode 文件断点续采。产物 `artifacts/v2_sft_500/buffer/`，两个 GPU 日志在其父目录。完成后生成 `success_once_summary.json`（总体及分 task）；也可随时运行 `scripts/summarize_collection.py <buffer目录>` 读取已落盘数据汇总。当前仅启动采集，未宣称完成。

此次为 SFT rollout 部分；expert demos 仍需另行准备。共用采集脚本只新增来源、初始状态编号和 success_once 字段，未更改 v5 算法。

## 2026-09-28：下载并转换 expert demos

- 官方 LIBERO downloader 指向的公开库 `yifengzhu-hf/LIBERO-datasets`，固定 revision `f13aa24a3da8c43c7225569f28c562979fa0e35a`。Spatial 10 个 HDF5、每任务 50 条，已全部下载。匿名访问避开本机过期 token。
- 原始数据为 **500 demos**，论文列出的 **432 demos 的具体筛选子集未确认**；不随意删到 432，也不声称数据条件完全一致。
- 官方 `create_dataset.py` 保存 post-action RGB/proprio 与 pre-action simulator states。转换使用每个 chunk 起点的 simulator state 重新渲染，统一 256px 和现有 observation adapter；最后的 next observation 通过末状态执行末动作获取。
- Demo 动作经过 checkpoint 实际 input transform（含 quantile normalization），再用 output transform 逐 chunk 往返校验。不足 5 步尾块用末动作补齐，steps/rewards 只保留实际长度。
- 单条 task0 demo0 转换通过：98 steps、20 chunks，动作往返最大误差 2.45e-7，末状态成功复核为 true。奖励保留官方标签，来源显式标注；末状态成功复核失败的样本不标为 eligible，不静默混入训练。
- tmux `qvgm-v2-demo-convert`：GPU 0、1 转换 demos；SFT 继续使用 GPU 2、3。此时两类数据尚未全部完成。
- `scripts/audit_dataset.py` 检查 source、task/episode 覆盖、观测/prefix shape 和有限值、逐步奖励、action、terminated/truncated、success_once，生成分来源 `dataset_report.json` 和 `combined_manifest.json`；只有两类数据各 500 条且检查通过才设置 ready=true。该 ready 是本地数据准备状态，不表示论文 432-demo 子集已匹配。
- `scripts/finish_dataset.sh` 等待两组任务结束，执行最终审计并写 `数据准备状态.md`。没有自动启动训练。

来源：[LIBERO 官方数据转换脚本](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/scripts/create_dataset.py)。后续还需核对本地 MuJoCo/控制器与原始 demo 环境版本差异，末状态成功复核不等于整条动作轨迹的动力学重放验证。
